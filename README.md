# Бот-ретранслятор для переписки с клиентами

Клиент пишет вашему боту → сообщение появляется **в вашей приватной группе Telegram**, в отдельном топике для каждого клиента → вы отвечаете прямо в топике → бот доставляет ваш ответ клиенту.

Никакого веб-интерфейса, никакого AI, никаких автоответов. Вы работаете в обычном Telegram.

```
                          ваша приватная группа
                          ┌──────────────────────┐
 Иван ──┐                 │ 📁 Иван Кузнецов     │
        │                 │ 📁 ТОО «Ромашка»     │
 Мария ─┼──► @ваш_бот ──► │ 📁 Мария             │ ◄── вы отвечаете
        │                 │ 📁 Алексей           │     прямо в топике
 Пётр ──┘                 └──────────────────────┘
```

---

## Что умеет

- Один клиент — один топик. Топик создаётся сам при первом обращении.
- Первым сообщением в топике — карточка клиента: имя, `@username`, Telegram ID, язык, дата первого обращения.
- **Любой тип сообщений в обе стороны**: текст, фото, файлы, голосовые, кружки, стикеры, геолокация. Ничего не теряется.
- Ваш ответ помечается 👌 после того, как он реально доставлен клиенту.
- Если доставить не удалось — в топик приходит понятная причина («клиент заблокировал бота»).
- Строка, начинающаяся с `//`, остаётся в топике и клиенту **не уходит** — внутренние заметки.
- Отвечать может любой участник группы. Хотите второго оператора — просто добавьте человека в группу.
- Повторная доставка вебхука не создаёт дублей, удалённый вручную топик пересоздаётся, лимиты Telegram соблюдаются.

**Ноль зависимостей в production.** Только Node.js 22. Хранилище — один файл SQLite через встроенный `node:sqlite`.

## Установка

### 1. Создать бота

[@BotFather](https://t.me/BotFather) → `/newbot` → скопируйте токен.

Сразу же, **это обязательно**:

```
/mybots → ваш бот → Bot Settings → Group Privacy → Turn off
```

Без этого бот не увидит ваши ответы в группе и ничего не отправит клиенту.

### 2. Создать группу

1. Создайте **приватную** группу в Telegram.
2. Добавьте в неё любого второго участника — Telegram сделает её супергруппой.
3. `Управление группой` → включите **«Темы»** (Topics).
4. Добавьте туда своего бота и сделайте его **администратором** с правом **«Управление темами»**.

> Если вы включили Group Privacy уже после добавления бота — удалите бота из группы и добавьте заново, иначе настройка не применится.

### 3. Запустить

```bash
npm install
cp .env.example .env
```

Впишите в `.env` токен, запустите:

```bash
npm run dev
```

Напишите что-нибудь в группе — в логе появится строка вида:

```
Если это ваша рабочая группа, укажите в .env:  GROUP_ID=-1001234567890
```

Впишите этот `GROUP_ID` в `.env` и перезапустите. Готово.

### 4. Проверить настройку

```bash
npm run setup
```

Проверит токен, группу, темы и права бота, подскажет, что не так.

## Как пользоваться

Клиент пишет боту → в группе появляется топик с его именем. Открываете топик, читаете, пишете ответ — клиент получает его от бота.

### Команды (пишутся в топике клиента)

| Команда | Что делает |
|---|---|
| `/info` | карточка клиента |
| `/id` | Telegram ID клиента (а в общем чате — ID группы) |
| `/close` | закрыть топик; новое сообщение клиента откроет его снова |
| `/ban` | перестать принимать и отправлять сообщения этому клиенту |
| `/unban` | снять игнор |
| `/stats` | сколько всего клиентов |
| `/help` | справка |

### Внутренние заметки

Сообщение, начинающееся с `//`, остаётся в топике и клиенту не уходит:

```
// клиент уже покупал в марте, дать скидку 10%
```

## Заявки с сайта

Бот умеет принимать заявки с формы на вашем сайте и складывать их в отдельную тему группы — по умолчанию она называется **«📥 Обращения с сайта»**. Тема создаётся автоматически при первой заявке, все последующие падают туда же.

### Включение

В `.env`:

```
LEADS_SECRET=<длинная случайная строка>
```

Пока эта переменная пуста — эндпоинт полностью выключен (любой запрос получит 404). Сгенерировать секрет:

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
```

### Контракт API

```
POST /leads/<LEADS_SECRET>
Content-Type: application/json

{
  "name": "Айдана",
  "company": "ТОО «Ромашка»",
  "telegram": "aidana_biz",
  "about": "Розница, 3 юрлица, учёт сейчас в Excel"   // необязательно
}
```

Поля `name`, `company`, `telegram` обязательны. `telegram` — username без пробелов, `@` в начале можно не ставить (нормализуется сама). Ответ:

- `200 {"ok":true}` — заявка доставлена в группу.
- `400 {"ok":false,"error":"..."}` — не хватает обязательного поля или username некорректен.
- `404` — неверный секрет в пути (или функция выключена).
- `502` — секрет верный, но Telegram недоступен (сеть, неверный токен и т.п.).

Проверить curl-ом:

```bash
curl -X POST https://ваш-сервер/leads/ВАШ_LEADS_SECRET \
  -H "Content-Type: application/json" \
  -d '{"name":"Тест","company":"ООО Тест","telegram":"test_user"}'
```

### Как подключить форму на сайте

Два способа, в зависимости от того, есть ли у сайта свой backend:

**Если есть backend (Next.js API route, любой сервер)** — отправляйте запрос **со стороны сервера сайта**, а не из браузера. Тогда простого `http://` до бота достаточно: это обычный серверный запрос, браузерные ограничения (HTTPS/CORS) на него не действуют.

**Если формы шлёт запрос прямо из браузера** (чистый HTML/JS без backend) — понадобится, чтобы адрес бота был на **HTTPS** с настоящим доменом: современные браузеры блокируют запрос с HTTPS-страницы на голый `http://IP-адрес` (mixed content). Понадобится домен, указывающий на сервер бота, и реверс-прокси с бесплатным сертификатом (проще всего — Caddy, полностью автоматический Let's Encrypt). Если у вас этот случай — напишите, добавим соответствующий раздел в DEPLOY.md.

В обоих случаях `LEADS_CORS_ORIGIN` в `.env` можно сузить до домена вашего сайта (по умолчанию открыт для всех).

## Production

Боту нужен постоянно работающий процесс. Подойдёт бесплатный тариф Railway, Fly.io или любой VPS.

**Пошаговая инструкция для бессрочно бесплатного варианта (Oracle Cloud Free Tier) — в [DEPLOY.md](DEPLOY.md).**

```bash
npm install && npm run build && npm start
```

**Режим polling** (проще всего) работает и в production — публичный адрес и https не нужны вообще. Для потока в несколько тысяч сообщений в день этого достаточно.

**Режим webhook** — если хотите, чтобы Telegram стучался к вам сам:

```
MODE=webhook
PORT=3000
PUBLIC_URL=https://bot.example.com
WEBHOOK_SECRET_PATH=<случайная строка>
WEBHOOK_SECRET_TOKEN=<случайная строка>
```

```bash
npm run set-webhook
```

Файл `data/relay.db` хранит привязку «клиент ↔ топик». **Его нужно сохранять между перезапусками** — на Railway/Fly подключите постоянный диск (volume). Если файл потерять, старые топики отвяжутся и клиентам создадутся новые.

## Ограничения

- **Все участники группы видят всю переписку.** Разграничения доступа нет — это плата за простоту. Держите группу приватной и приглашайте только тех, кому доверяете.
- Клиенты пишут **боту**, а не вашему личному аккаунту, и ответ приходит от бота с плашкой «BOT». Так работает Bot API: бот не может читать личные чаты вашего аккаунта.
- Бот не может написать клиенту первым — диалог всегда начинает клиент. Рассылки невозможны.
- Альбом из нескольких фото придёт в топик отдельными сообщениями.
- Редактирование сообщения клиентом в топике не отражается — придёт только исходный текст.
- Нет поиска по истории и статистики: история живёт в самом Telegram, ищите его поиском по группе.

## Структура

```
src/
  config.ts          настройки из .env
  env.ts             загрузчик .env (чтобы не тянуть зависимость)
  log.ts             логи
  telegram.ts        клиент Bot API: повторы, лимиты, разбор ошибок
  store.ts           SQLite: привязка клиент ↔ топик, дедупликация
  relay.ts           вся логика ретрансляции и команды
  poller.ts          режим long-polling
  webhook.ts         режим webhook (http-сервер без зависимостей)
  index.ts           запуск
  scripts/setup.ts   диагностика настройки
  scripts/set-webhook.ts
  tests/             заглушка Bot API + 41 проверка
```
